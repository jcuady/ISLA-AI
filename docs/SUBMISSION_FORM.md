```
Isla AI is an on-device AI compliance copilot for Philippine banks. Staff need
privacy-law answers in seconds, but their only fast option — pasting customer
data into a cloud AI — is exactly what Philippine banks are barred from doing.
You cannot check whether data is sensitive without first sending it, so Isla AI
runs entirely on the bank's own hardware: it redacts Philippine banking PII and
then re-runs its own detector over its own output, screens transactions for
fraud and AML risk against 20 named typologies, and answers Data Privacy Act
questions with the exact section quoted rather than written from memory. Where
a rule cannot be verified it names the gap instead of inventing it.
```

## 8 · Technical Disclosures*

```
MODELS USED
- intfloat/multilingual-e5-small, int8 ONNX (113 MB, MIT) — retrieval embeddings.
  Loaded and used.
- Qwen/Qwen2.5-3B-Instruct-GGUF Q4_K_M (2.0 GB, Apache-2.0) — optional generation
  via llama.cpp. Present but NOT loaded; every published metric was measured
  without it.
- urchade/gliner_multi-v2.1 (1.1 GB, Apache-2.0) — optional contextual NER.
  Download did not complete on the development machine and it was never run.
  No published metric depends on it.

TECHNOLOGIES AND FRAMEWORKS
Python 3.12, FastAPI, Uvicorn, Pydantic v2, ONNX Runtime, Transformers,
PyTorch (CPU), rank-bm25, PyMuPDF, llama.cpp, React 18, TypeScript, Vite,
Tailwind CSS, Radix UI, pytest, Vitest, Playwright, GitHub Actions.

APIS AND CLOUD SERVICES
None at runtime. No cloud AI provider is installed, called or reachable. No
telemetry, no analytics, no error reporting, no update pings. Hugging Face Hub,
lawphil.net and web.archive.org are contacted at build time only, to fetch model
weights and public legal texts. Stated precisely rather than in the
stronger-sounding form: the air-gap probe does open a real TCP connection to
public resolvers, sending a handshake and no payload, so the air-gap claim can
be falsified live. Nothing else in the runtime holds a network primitive, and a
test enforces that.

EXISTING CODE AND ASSETS
- Model weights and the llama.cpp binary (tag pinned to b11515) are third-party,
  fetched at install time and never committed to the repository; every download
  is SHA-256 recorded.
- The legal corpus is entirely unmodified public government publications, with
  URL, retrieval date and SHA-256 recorded per document. Nothing proprietary.
- The logo and brand identity are original, created for this project.
- All evaluation datasets are synthetic and hand-built for this project. No real
  customer records were used anywhere.

AI DEVELOPMENT TOOLS
Disclosed per the competition rules. MiniMax Code (mavis agent) was the primary
development assistant and ran the build end to end — architecture,
implementation, debugging, test authoring, the evaluation harness, the UI and the
documentation. AI image generation produced the logo mark and the hero
photograph. Archify produced the architecture diagram. The architecture, product
decisions, model selection and all verification are the team's. No generated code
was committed without being read, run and verified. Every published metric is
regenerated by running the committed code; where a metric was missed it is
reported as missed.

KNOWN LIMITATIONS, DISCLOSED
BSP, SEC and AMLC circulars are not in the corpus — those sites refuse the
development machine and no usable archive capture exists — so the product names
each gap on every relevant answer instead of quoting a circular it cannot
verify. RA 9160's public copy is abridged, so no reporting deadline is quoted.
One question in five attributes its answer to the wrong instrument; this is a
measured coverage gap rather than a reasoning failure, and the fix is more
documents rather than more tuning. Nothing in this project has been audited
against any certification or standard.
```
